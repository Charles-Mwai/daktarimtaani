Rewire the patient consult flow (track / room / summary) from the legacy localStorage store to the DB-backed API, so home-visit tracking loads and doctor actions (arrival, Rx & close, end of consult) reflect live on the patient side.

## Root cause
- Requests created via `POST /api/requests` exist only in Prisma. `track`/`room`/`summary` pages look them up in `localStorage` (`lib/store.ts`) → never found → eternal "Loading home visit tracking...".
- Doctor's "Write Rx & Close" (`POST /api/clinical-records`) sets DB `status: 'completed'` + saves prescriptions, but patient pages never read the DB, so nothing reflects. Also `arrived`/`consulting` statuses are never settable in the DB at all.

## Changes

**1. `src/app/api/requests/[id]/route.ts` — enrich + add PATCH**
- GET: include `doctor` (DoctorProfile + user phone for the call button), `clinicalRecord` (with `prescriptionsJson` parsed into a `prescriptions` array), and `payment`. Extra keys are backward-compatible with the matching page.
- PATCH: `{ status: 'arrived' | 'consulting' }` → sets the matching timestamp (`arrivedAt` / `consultStartedAt`) + audit log. This lets the doctor drive the visit lifecycle in the DB.

**2. Rewrite `src/app/patient/consult/[id]/track/page.tsx`**
- Poll `GET /api/requests/[id]` every 2–3s (same pattern as the working matching page); 404 → "request not found" state instead of hanging.
- Build `LocationCoordinates` from flat request/doctor DB fields to feed `MapTracker` (real coords, simulated movement kept).
- Status-driven UI: `in_transit` → live map + doctor card + security code; `arrived`/`consulting` → "Doctor has arrived / consultation in progress" banner (map pin docks at patient, ETA 0); `completed` → "Visit concluded" with button to summary. Remove the patient-side localStorage mutation ("Doctor Has Arrived" button no longer writes fake status).

**3. Rewrite `src/app/patient/consult/[id]/room/page.tsx` (teleconsult)**
- API polling; on mount PATCH `consulting` if still `accepted`.
- When status becomes `completed` (doctor closed with Rx) → banner "Doctor has ended the consultation" + auto-redirect to summary. Patient's End Call still navigates to summary.

**4. Rewrite `src/app/patient/consult/[id]/summary/page.tsx`**
- Fetch request + doctor + clinical record + payment from the enriched API. **Remove the fabricated/hardcoded clinical record** — if the doctor hasn't submitted yet, show "Doctor is finalizing clinical notes…" with polling, so it appears the moment the doctor prescribes.
- Display real prescriptions, impression, vitals; payment state from `payment.status` / `request.paidAt`.
- `isPaid` check + "Pay via M-Pesa" uses the real simulated endpoint.

**5. `src/components/MpesaModal.tsx`**
- Replace the legacy-store write with `POST /api/payments/simulate`; surface the returned receipt number.

**6. `src/components/MapTracker.tsx`**
- Small addition: optional `arrived` prop to freeze the doctor pin at the patient location (ETA 0) instead of stalling at 95%.

**7. `src/app/doctor/page.tsx` — visit lifecycle actions**
- Home-visit rows get "Mark Arrived" and "Start Consultation" buttons (PATCH the status), alongside existing "Write Rx & Close". This gives the patient track page real progression.

**8. New `src/app/api/ratings/route.ts`**
- Small POST endpoint persisting the patient star rating + comment to the existing `Rating` model (summary page currently only writes localStorage). Audit-logged.

**9. MapTracker/track "Live GPS" wording** stays honest-ish but unchanged visually otherwise.

## Not in scope (follow-ups)
- `/patient/records` and `/doctor/earnings` still on the legacy store; real WebRTC; real M-Pesa Daraja; API auth checks.
